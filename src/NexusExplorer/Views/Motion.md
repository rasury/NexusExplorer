# 动画维护说明

## 职责与入口

应用自有动画只通过 `PrismMotion.Animate` 执行。三个部分各有职责：

- `MotionProfiles`：按交互用途集中配置时间、曲线、弹簧阻尼/频率和悬停延迟。
- `MotionAnimation`：由 WPF AnimationClock 驱动，解析计算弹簧或平滑 Hermite 曲线，同时提供位置与速度。不创建逐帧关键帧对象，不自建计时渲染循环。
- `PrismMotion`：每个对象/属性只有一个活动通道；替换时继承当前位置和速度；旧完成回调不再生效；结束时释放时钟并保留最终值与绑定。卸载/关闭时调用 Stop/StopAll。

控件只决定目标状态、目标值与业务完成动作。不要在控件内新建动画、复制弹簧公式或散落时长。

## 交互清单

| 用途 | 配置 | 执行动画的属性/触发 |
| --- | --- | --- |
| 左侧收放、动态卡片高度、右侧详情 | Panel：700ms，阻尼0.72，角频率18 | 点击收放、列表变化、详情悬停；位置/缩放及必要的布局尺寸 |
| 搜索范围文字切换 | Scope：500ms，阻尼0.72，角频率24 | 点击后 TranslateTransform.X |
| 通知进入 | NoticeEnter：820ms，阻尼0.58，角频率18 | 新通知 TranslateTransform.Y，允许过冲回弹 |
| 通知退出 | NoticeExit：300ms 平滑曲线 | 保持500ms后平滑退出；新通知可中途接管 |
| 侧栏淡出入 | Fade：700ms 平滑曲线 | Opacity，限制在0～1，与侧栏运动周期协调 |
| 按压反馈 | Press：140ms 平滑曲线，深度1.5 | 鼠标按下/释放/离开；追加专用 TranslateTransform，不覆盖原变换 |
| 弹窗进入 | DialogEnter：220ms，阻尼0.78，角频率30；DialogFade：160ms | 12px位移与淡入，避免从零尺寸缩放；包含独立输入窗口 |
| 弹窗退出 | DialogExit：120ms 平滑曲线 | 先淡出和位移，完成后才允许 DialogSession 关闭、移除内容和销毁输入窗口 |

详情进入200ms、离开180ms；音量离开250ms；悬停检查40ms。它们是触发延迟，不是帧率。业务异步加载、搜索防抖、双击判定不属于动画执行层。

MaterialDesign 的 Ripple、音量 Popup 模板内部过渡继续由框架负责；系统窗口最小化/最大化由 Windows 负责。DialogHost 保留模态、焦点和会话管理，清除其 PopupStates 的默认过渡，卡片进退场统一交给 PrismMotion，避免两套动画叠加。关闭请求在退出期间取消并合并，动画完成后携带原参数真正关闭；应用退出则直接取消。运动期间使用 WPF BitmapCache，结束后释放；内容变化仍可使缓存失效，未使用冻结背景截图。

## 布局与玻璃性能

通知、文字、按压以及侧栏自身的位移/缩放使用渲染属性。侧栏占位、卡片高度及详情宽度需要真实改变内容排版和原生视频窗口尺寸，保留布局动画；写入尺寸按设备像素取整，只有有效尺寸变化才更新。侧栏负方向过冲仍通过占位与边距表达。

没有使用截图替代视频或缩放文字来伪造布局。模糊、阴影、实时背景采样保留原质量。

玻璃卡片合并脏更新：同一次调度共享一个 Render 优先级队列，复用裁剪几何，缓存场景引用，使用同视觉树坐标转换代替重复屏幕坐标转换。该队列面向当前应用单 UI Dispatcher；若未来引入多 UI 线程，应先按 Dispatcher 隔离队列。

原生视频裁剪仅在尺寸/圆角变化时重建区域；测试覆盖侧栏收放、窗口平移后圆角仍有效。

## 验证与测量（2026-10-23）

最小功能检查覆盖：反向切换的位置/速度连续性、旧回调失效、动画结束释放时钟、快速侧栏/详情反向切换、通知替换、搜索文字最终状态、列表虚拟化、浅深主题背景，以及原生视频点击暂停/恢复/全屏和圆角。

性能用 `AnimationPerformanceTests.MeasureProductionMotion` 在 Release、1000条文件、玻璃效果开启时测量，每种交互两轮，每轮850ms。通过 `NEXUS_MOTION_REPORT` 指定报告后缀，JSON 输出到临时目录 `nexus-feature-checks/motion-*.json`。仅运行该测试即可复测，无需完整测试集。

新增动画时选择现有角色配置；确有不同用途才新增配置。对可逆动画补充中途反向和最终状态检查；布局动画须解释为何需要真实排版，并用上述测试复测。不要增加固定FPS限制或为追求数字而关闭玻璃效果。

## 主题切换

`ThemeTransition` 在用户切换深浅主题时各捕获一次主窗口 WPF 表面和当前弹窗，更新真实主题后，用纵向柔边透明遮罩揭开新主题。两个表面按屏幕位置共享自上而下的推进线。时长与柔边宽度集中在 `MotionProfiles.Theme` / `ThemeFeather`；只有遮罩的两个 GradientStop.Offset 使用 PrismMotion，不逐帧截图或修改布局。

过渡期间外观设置禁用操作；重复请求不会重新启动动画。完成、窗口尺寸变化、卸载或 Dispatcher 退出时释放遮罩、快照和时钟。旧主题过渡快照边长最多720像素，过渡层可能暂时较软，被揭开的新主题始终使用实时全分辨率界面。快照只包含WPF，原生视频HWND继续实时显示，不截取或替换视频画面。启动和同明暗模式切换仍立即应用；Windows系统主题自动更新保留原行为。

2026-10-24：主题过渡使用550ms零初速度的三次Hermite曲线（慢—快—慢，无过冲），柔边宽度为窗口高度12%。原同步截图在AppearancePreviewTests的5次切换中耗时370–621ms，改为720像素过渡快照后为89–163ms；准备总时间从396–793ms降为178–350ms。该数据为同机Debug真实WPF窗口短样本，不代表实际显示帧延迟或所有硬件。日志分别记录截图和主题资源应用耗时，便于继续定位；资源应用仍可能超过100ms，不承诺零延迟。
