# 重构评估与实现说明

审查与实现基线：0a3c02f，Windows x64，2026-10-03。需求顺序：本次明确要求 > 已确认当前行为/移交说明 > 第一版文档。

## 基线风险

1. 原仓库缺失 AppDbContext，忽略规则 data/ 误覆盖源码 Data 目录，无法可信构建。
2. 分类改名、移动只更新分类绝对路径，文件记录失效；归属与存储位置混用，分类删除可能误回收其他文件。
3. 文件先搬走、最后批量保存数据库；取消或提交失败留下文件与记录不一致。冲突替换永久删除目标，没有补偿。
4. WPF 视频共享缓冲区与原生写入/旧媒体清理没有完整同步，存在竞态和渲染开销；多入口并行启动/停止/seek，媒体资源释放顺序错误。
5. 树重建丢状态、文件拖拽读取旧选择、滚动条命中穿透、分类根目标缺失。
6. 冲突窗口将 TextBlock 样式用于 CheckBox；取消、应用到全部未完整传递。
7. 测试缺媒体时返回并记为通过，若干用例只测试复制逻辑。

## 数据操作边界

- 旧库先备份并在副本迁移；无法识别或存在歧义时停止。
- 文件系统与 SQLite 无法共同事务化，采用持久日志＋复制/校验＋逐项提交＋补偿；原件保留到数据库提交成功。
- 回滚只操作本次创建的目标，不删除复制期间其他程序创建的目录；内容被外部更改则保留现场。
- 回收站失败/数据库失败/单项取消均报告部分结果。批次不是全有或全无事务，完成项保持一致。
- 完整目录迁移复制未登记文件；删除分类只回收逻辑子树所属的已登记文件。
- 符号链接/联接点搬迁暂不支持，遇到时拒绝并保留现场。
- 整理取消在文件提交边界生效，不强行中断正在复制的单项；因此大文件取消和退出需等待。
- 大目录迁移会占用额外磁盘空间，目录删除只保留空目录回收；内容变化的现场需人工核对。
- 只有大小写发生变化的分类改名更新逻辑名称，物理目录拼写保持原样，路径有效。
