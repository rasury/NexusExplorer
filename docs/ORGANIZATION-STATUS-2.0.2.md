# 2.0.2 分类整理状态

采用持久化的保守确认状态，避免在显示分类时遍历全部绑定文件地址。

- 橙色 **↗ 待整理**：新分类、旧库升级后的分类，或绑定数据、分类目录发生变动。即使所有文件已经在本目录，尚未整理确认时也保持此标识。
- 绿色 **✓ 已整理**：上次递归整理任务全部成功结束。本分类直接绑定的文件已登记到自己的分类目录，子分类也分别整理到各自目录。
- 添加、归类、移除、删除、重新定位文件会重置相关分类；归类重置原分类和目标分类。分类改名、移动、迁移、重新定位及子分类结构变动也保守重置相关分类。
- 分类排序、快捷标签排序、钉住与取消钉住、普通浏览不重置状态。
- 整理开始时先持久化“待整理”。取消、源文件缺失、文件锁、冲突失败或异常退出不会产生“已整理”。整批成功才更新整个子树；空分类也可通过成功整理获得确认。
- 重名“跳过”且成功改用尚未登记的目标文件，计为成功；目标已经有记录则失败，保持待整理。
- 标识在分类树、底栏导航和快捷分类同时显示，重启后保留；状态更新不重建分类树、不清空展开状态。

这是上次整理确认记录。软件外部移动或删除文件不会实时改变标识，可再次整理确认。

## 数据与性能

数据库版本为 3。升级前使用 SQLite 在线备份（包含 WAL），在副本上添加 IsOrganized 和失效触发器，再写回成功副本。旧分类默认未确认。v2 升级保留目录位置、文件路径、分类 ID 及独立快捷排序，不重新扫描绑定文件。

文件变更的失效触发器只按相关分类主键更新，和文件记录修改属于同一数据库事务。界面刷新只查询分类 Id、IsOrganized，整理过程中沿用已有文件处理结果确认完成，不另做一轮文件扫描。

## 验收

1. 启动 2.0.2：未整理过的分类显示橙色；分类树和快捷标签一致。
2. 整理一个分类：包括子分类的所有项目成功后，本次子树显示绿色；重启仍为绿色。
3. 向绿色分类添加文件，即使文件已经位于本目录，也变为橙色。
4. 将文件从绿色 A 归入绿色 B：A、B 都变为橙色。
5. 从绿色分类移除或删除文件、重新定位文件、重命名或移动分类：相关分类变为橙色。
6. 再次完整整理恢复绿色；调整分类或快捷排序、钉住与取消钉住不改变绿色。
7. 制造源文件缺失、文件锁或已登记目标重名，或取消整理：即使部分文件已处理成功，整批子树保持橙色。
8. 分类展开状态在文件变更和标识刷新后保持。

自动化验证涵盖真实 SQLite 触发器与事务回滚、v2 副本迁移、状态重启持久化、递归成功与各种失败/取消、实际 WPF 模板绑定。性能回归将 Files 表改名为不可查询后，分类树及状态查询仍能成功，确认显示不依赖读取绑定文件。
